# APG V14 — Commercial Product Layer

V14 moves APG from a partner directory toward a real automotive marketplace and partner CRM.

## Core domains

### Customer
- Browse active partner offers.
- Open a company profile with gallery, services and reviews.
- Book a service slot.
- Create an order for a service.
- Track order status.
- Generate one-time discount QR codes.
- Keep a garage without a car-brand field.
- Earn and inspect APG Bonus points.
- Receive notifications.

### Seller
- Work only with assigned companies.
- Review bookings and orders for assigned companies.
- View customer CRM records generated by interactions.
- Add internal CRM notes.
- Inspect event analytics.
- Moderate/operate the seller side without access to other sellers' companies.

### Owner
- Global customer and seller administration.
- Partner company management.
- Offer moderation.
- Gallery, service and review moderation.
- Partner plans and subscription layer.
- Payment-intent monitoring.
- Loyalty point awards.
- Audit log.
- Analytics.

## Payment architecture

The API creates a payment intent and a stable APG checkout reference. The default provider is deliberately a mock adapter so a production payment provider can be attached without pretending that a card charge occurred. A Stripe/Adyen adapter should implement the same lifecycle: `created -> requires_action -> succeeded|failed|cancelled` and verify webhooks server-side.

## Loyalty architecture

Points are immutable transactions plus a cached account balance. Owner actions create a transaction and notify the customer. Production should add a rule engine for completed orders, QR redemptions, referrals and promotional campaigns.

## CRM architecture

CRM records are derived from bookings and orders. Internal notes are scoped to a company and customer. Seller access is checked against `seller_companies` before a note is written or company-specific settings are changed.

## Analytics events

The frontend can send lightweight events such as `company_view`, `offer_view`, `qr_created`, `booking_created`, `order_created`, `review_submitted`, and `favorite_added`. The current API aggregates counts; production can move events into an analytics warehouse later.

## Release checklist

1. Set a strong `APG_SECRET_KEY`.
2. Use PostgreSQL on Render.
3. Set `APG_COOKIE_SECURE=1` behind HTTPS.
4. Configure S3-compatible object storage for durable uploads.
5. Connect a real payment provider and webhook verifier.
6. Configure FCM/APNs credentials for push.
7. Add production domain and email sender.
8. Run database migrations before deployment.
9. Enable backups and monitoring.
10. Perform App Store / Google Play privacy and permission review.
